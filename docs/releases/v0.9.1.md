# Vibe Coding Production Kit v0.9.1

VCP v0.9.1 is a dogfood-driven patch release focused on making the framework easier to use through coding agents and on closing workflow gaps discovered while running v0.9.0 end to end.

## Highlights

### Agent-first usage

The intended human experience is now explicit:

```text
Developer states intent
      ↓
Agent inspects repository + drafts VCP artifacts
      ↓
Developer answers only unresolved human-intent decisions
      ↓
Agent drives task → readiness → context → implementation → verification → review
      ↓
Developer reviews plan, trade-offs, evidence, and result
```

`AGENTS.md`, Quickstart, Start Here, CLI docs, Task Packs, Context Packs, and both READMEs now reinforce this split.

### JavaScript / Node.js profile

Repositories with `package.json` and no TypeScript marker are now detected as JavaScript/Node.js instead of falling back to `generic`.

VCP reuses existing package scripts such as `check`, `test`, `test:unit`, `test:integration`, `build`, `test:e2e`, and `e2e` when present. It does not invent missing commands.

### Readiness and verification agree

`vcp ready <task> --stage implement` now requires at least one executable task verification command other than `INSTALL_COMMAND`.

A task can no longer report implementation-ready and then immediately fail because `vcp verify` has no runnable plan.

### Reasoned non-applicable commands stay non-executable

Values such as:

```text
TYPECHECK_COMMAND=n/a — plain JavaScript
BUILD_COMMAND=n/a - no build step
E2E_COMMAND=not applicable — no UI
```

are treated as explicit engineering decisions, not shell commands. This applies both when generating new task packs and when parsing existing task verification sections.

### Stronger task/source-of-truth diagnostics

Readiness now:

- rejects duplicate level-two task sections that would make parsing ambiguous;
- warns when referenced Source of Truth files still contain known starter-template signals;
- keeps reasoned `n/a — <reason>` statements valid where the task section allows non-applicability.

### Lifecycle-safe 0.9.1 update

The package includes an explicit lifecycle migration:

```text
0.9.0 → 0.9.1
```

which composes with the historical path:

```text
0.8.0 → 0.9.0 → 0.9.1
```

No rename or removal is required for this patch release; the migration advances lifecycle state explicitly and safely.

## Verification

Validated on Windows with Node.js 24.5.0 and npm 11.5.2:

- framework validation passed;
- syntax check passed for 24 modules;
- test suite passed: 116/116, 0 failures;
- `npm run pack:check` passed;
- `npm publish --dry-run` passed;
- package dry-run contained 88 files and reported version 0.9.1.

GitHub Actions still fails before executing workflow steps on the maintainer account, so that infrastructure failure is not treated as source-test evidence.

## Release safety

- The existing `v0.9.0` tag remains untouched.
- npm `0.9.0` remains immutable and is not republished.
- `v0.9.1` is the patch release for these fixes.
