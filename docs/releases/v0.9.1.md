# Vibe Coding Production Kit v0.9.1 — Release Candidate

VCP v0.9.1 is a dogfood-driven patch release focused on making the framework easier for developers to use through coding agents and on closing workflow gaps discovered while running v0.9.0 end to end.

This document describes the release candidate in PR #6. It does **not** mean v0.9.1 has been published to npm or tagged on GitHub yet.

## Highlights

### Agent-first usage

The intended human experience is now explicit:

```text
Developer states intent
      ↓
Agent inspects repository + drafts VCP artifacts
      ↓
Developer answers only unresolved human-intent decisions
      ↓
Agent drives task → readiness → context → implementation → verification → review
      ↓
Developer reviews plan, trade-offs, evidence, and result
```

`AGENTS.md`, Quickstart, Start Here, CLI docs, Task Packs, Context Packs, and both READMEs now reinforce this split.

### JavaScript / Node.js profile

Repositories with `package.json` and no TypeScript marker are now detected as JavaScript/Node.js instead of falling back to `generic`.

VCP can reuse existing package scripts such as:

```text
check
test
test:unit
test:integration
build
test:e2e
e2e
```

It does not invent missing commands.

### Readiness and verification agree

`vcp ready <task> --stage implement` now requires at least one executable task verification command other than `INSTALL_COMMAND`.

A task can no longer report implementation-ready and then immediately fail because `vcp verify` has no runnable plan.

### Reasoned non-applicable commands stay non-executable

Values such as:

```text
TYPECHECK_COMMAND=n/a — plain JavaScript
BUILD_COMMAND=n/a - no build step
E2E_COMMAND=not applicable — no UI
```

are treated as explicit engineering decisions, not shell commands. This applies both when generating new task packs and when parsing existing task verification sections.

### Stronger task/source-of-truth diagnostics

Readiness now:

- rejects duplicate level-two task sections that would make parsing ambiguous;
- warns when referenced Source of Truth files still contain known starter-template signals;
- keeps reasoned `n/a — <reason>` statements valid where the task section allows non-applicability.

### Lifecycle-safe 0.9.1 update

The package version is prepared as `0.9.1` with an explicit migration:

```text
0.9.0 → 0.9.1
```

The migration composes with the existing historical path:

```text
0.8.0 → 0.9.0 → 0.9.1
```

No rename or removal is required for this patch release; the migration exists so lifecycle state advances explicitly and safely.

## Verification status

The release candidate adds regression coverage for:

- JavaScript package-script inference;
- reasoned `n/a` handling in agent configuration and task verification parsing;
- readiness/verify alignment;
- duplicate task sections;
- starter-template Source of Truth warnings;
- `0.9.0 → 0.9.1` and composed migration paths.

Targeted isolated checks have passed on Node 22.16.0 for the verification parser and migration logic.

Before publishing, the release candidate still requires a real repository checkout to pass:

```bash
npm run validate
npm run pack:check
npm publish --dry-run
```

GitHub Actions currently fails before executing workflow steps on the maintainer account, so that infrastructure failure is not treated as source-test evidence.

## Release safety

- Do not move or recreate the existing `v0.9.0` tag.
- Do not republish `0.9.0`; npm versions are immutable.
- Publish fixes only as `0.9.1` or later.
- Create the `v0.9.1` tag and GitHub Release only after the full validation and package dry-run gates pass.
