# Vibe Coding Production Kit v0.9.2

VCP v0.9.2 is a focused follow-up to the first clean-room agent-first dogfood of v0.9.1. It keeps the successful control-plane workflow intact while fixing two places where the CLI/documentation contract could mislead an autonomous coding agent.

## Highlights

### Greenfield implementation context is now explicit

`vcp context --include` remains strict: it means the referenced repository-local file exists and its current contents should be included.

For a new implementation path that does not exist yet, use:

```text
vcp context <task> --mode implement --planned src/new-file.mjs
```

`--planned` is repeatable and implement-mode only. It records the approved future path in the bounded context pack without inventing file contents.

This fixes the dogfood sequencing gap where the documented workflow asked the agent to build implementation context before coding while `--include` required the greenfield files to already exist.

### Doctor strict-mode coverage is explicit

A green `vcp doctor . --strict` means every check currently defined by Doctor is green; it does not claim that every VCP-installed document has been customized.

Doctor now reports coverage metadata in both human-readable and JSON output:

- five core decision documents receive known starter-template marker checks;
- Definition of Ready and Definition of Done are presence-only core checks;
- `USER-FLOWS.md`, `DOMAIN.md`, and `DATA-MODEL.md` remain outside universal template-completeness enforcement.

This preserves project flexibility while avoiding false confidence from an implicit coverage boundary.

## Agent-first workflow impact

The intended experience remains:

```text
Developer states intent
      ↓
Agent inspects/drafts/runs VCP
      ↓
Developer resolves only genuine human-intent decisions
      ↓
Agent plans within bounded context
      ↓
Agent implements + verifies
      ↓
Developer reviews plan, evidence, and result
```

For implementation context specifically:

```text
existing affected file → --include
approved future file    → --planned
```

## Lifecycle

```text
0.9.1 → 0.9.2
```

which composes with the existing historical chain:

```text
0.8.0 → 0.9.0 → 0.9.1 → 0.9.2
```

No rename or removal is required for this patch release.

## Regression coverage

The v0.9.2 changes add tests for:

- greenfield planned source/test paths in implement context;
- rejecting `--planned` outside implement mode;
- rejecting `--planned` when the file already exists and should use `--include`;
- path traversal protection for planned paths;
- portable planned-path rendering;
- CLI `--planned` behavior;
- Doctor coverage metadata and human-readable coverage reporting;
- migration composition from 0.9.1, 0.9.0, and 0.8.0 to 0.9.2.

## Validation status

Release validation is intentionally not claimed here until the branch has passed local framework validation, syntax checks, the full test suite, package dry-run, and published-package lifecycle dogfood.

GitHub Actions on the maintainer account has historically failed before workflow steps execute, so runner infrastructure status is not treated as source-test evidence.
